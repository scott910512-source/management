🖥️ dev-coder × TotalPilot 개발환경 구성 보고서

사내 dev-coder(Coder 기반 클라우드 개발환경)와 수불관리 시스템(StockPilot·ManagePilot)을 엮은 VDI 내 개발 체계 구성안과 그 장점 정리

AI DevBox 워크스페이스 VS Code + Claude Code StockPilot · ManagePilot VDI 보안망 내 완결

1. dev-coder 주요 기능

기능내용우리 시스템과의 연결점
워크스페이스 개인 전용 개발 서버(컨테이너). AWS 위에서 돌아가며 브라우저만 있으면 어디서나 접속. 현재 management 워크스페이스 배정됨. 수불관리 시스템 코드 전체를 이 안에서 개발·실행
AI DevBox 템플릿 VS Code(원격) + Claude Code 연동이 미리 세팅된 표준 환경. 관리자가 템플릿을 갱신하면 전 사용자 환경이 동일하게 유지됨. 개인 PC 세팅 없이 즉시 개발 시작
VS Code 원격 접속 로컬 VS Code 또는 브라우저에서 워크스페이스로 바로 연결. 코드·터미널·디버깅 전부 서버에서 실행. 빌드(npm run build)·테스트를 서버 자원으로 수행
Claude Code 연동 워크스페이스 안에서 AI에게 코드 수정·버그 조사·테스트 작성을 직접 시킬 수 있음. 지금까지 세션에서 하던 작업(FIFO 수정, 화면 개선 등)을 VDI 안에서 직접 수행
포트 포워딩 워크스페이스 안에서 띄운 서버(예: localhost:4000)를 브라우저로 접근 가능. 수불관리 서버를 띄워 실제 화면으로 즉시 확인·시연
자동 중지 / 재시작 미사용 시 자동으로 꺼져 비용 절감. 다시 접속하면 재시작. 홈 디렉토리는 유지되므로 코드는 안전 (단, 실행 중이던 서버는 재기동 필요)

2. VDI 내 TotalPilot 개발 체계 구성안

권장 폴더 구성 (워크스페이스 홈 디렉토리 기준)

경로내용
~/management_code/server백엔드 (Node/Express) — server/data는 개발용 데모 데이터만
~/management_code/client프론트엔드 (React/Vite) — 여기서 npm run build
git 저장소 연결모든 변경은 커밋/푸시 — 워크스페이스 재빌드에도 코드 유실 없음

개발 → 운영 반영 흐름

① 개발 (dev-coder)Claude Code에게 수정 지시 → 코드 변경 → 테스트 실행
② 검증 (dev-coder)서버 기동 + 포트 포워딩으로 화면 직접 확인
③ 커밋/푸시git으로 변경 이력 보존
④ 운영 반영운영 서버에 변경 파일 + dist 교체 후 재시작

모듈별 개발환경 특이사항

3. 이 구성의 장점

🔒
보안망 내 완결

코드·데이터가 회사 AWS/VDI 밖으로 나가지 않음. 개인 PC에 소스를 보관할 필요가 없어 유출 위험 감소.

⚡
개발 속도

Claude Code가 워크스페이스 안에서 직접 코드를 고치고 테스트까지 돌림 — 파일을 주고받으며 수동 반영하던 현재 방식 대비 왕복 시간 대폭 단축.

🖥️
PC 성능 무관

빌드·테스트가 서버 자원으로 실행. 로컬 PC가 느려도, npm/node 설치가 안 돼 있어도 무관 (vite 미설치로 빌드 실패했던 문제 원천 해소).

🧪
안전한 실험

운영과 완전히 분리된 환경 — 데모 데이터로 마음껏 테스트하고, 실패해도 운영에 영향 없음. 워크스페이스는 새로 만들면 그만.

📜
이력 관리 일원화

모든 변경이 git 커밋으로 남음. "어느 파일을 언제 바꿨는지" 추적 가능, 문제 시 이전 버전으로 복구.

🌐
어디서나 동일 환경

사무실·재택 어디서든 브라우저로 같은 환경에 접속. 자리를 옮겨도 작업 상태 그대로.

4. 운영 시 주의사항

⚠ 홈 디렉토리 밖은 초기화될 수 있음 — 워크스페이스 재빌드(템플릿 업데이트) 시 홈(~/) 밖에 둔 파일은 사라질 수 있습니다. 코드는 반드시 홈 아래 + git 커밋으로 이중 보관하세요.
⚠ 자동 중지 — 장시간 미사용 시 워크스페이스가 자동으로 꺼집니다. 띄워둔 개발 서버는 재접속 후 다시 실행해야 합니다. 긴 작업은 tmux/nohup 안에서 실행 권장.
⚠ 리소스 한도 — 무거운 작업 시 "Attempting to reconnect" 끊김이 발생하면 워크스페이스 메모리 부족일 가능성이 높습니다. free -h로 확인 후 필요 시 관리자에게 사양 상향 요청.
⚠ 운영 데이터 분리 원칙 — dev-coder의 server/data는 데모 전용입니다. 운영 서버의 실제 데이터 폴더는 절대 dev 환경 파일로 덮어쓰지 않습니다.

5. 요약

dev-coder는 "개발·검증은 클라우드 워크스페이스에서, 운영 반영은 검증된 파일만"이라는 체계를 만들어 줍니다. 지금까지는 파일 전달 → 수동 교체 → 빌드 실패 시 재요청 방식이었다면, dev-coder 도입 후에는 워크스페이스에서 수정·빌드·화면검증 완료 → 운영에는 결과물만 반영으로 단순해집니다. 특히 Claude Code가 워크스페이스 안에서 직접 작업하므로, 이번 세션에서 진행한 것과 같은 버그 수정·기능 추가·화면 검증(headless 브라우저 테스트 포함)을 모두 VDI 보안망 안에서 수행할 수 있습니다.
